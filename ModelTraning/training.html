Treinamento de Wake Word

Para treinar uma wake word, primeiro voce precisa ter dados de treinamento: uma pasta com arquivos .wav positivos da palavra ou frase que deve ativar o sistema. Neste projeto, esses audios podem ser criados pelo fluxo em DataGeneration.

O treino nao precisa saber o texto da wake word. Ele aprende pelos exemplos positivos da pasta. O nome do modelo e inferido pelo nome da pasta, e pode ser sobrescrito com --model-name.

Visao geral

Entrada

Uma pasta com WAVs positivos. Exemplo:

DataGeneration/Dataset-Atlas
Obrigatorio

Saida

Um modelo ONNX pronto para usar com openwakeword. Exemplo:

ModelTraning/models/atlas.onnx
Gerado pelo treino

Arquitetura do processo

  1. Geracao dos dados positivos: use DataGeneration para criar WAVs da wake word.
  2. Assets negativos: baixe features negativas genericas usadas para ensinar o modelo a nao ativar com qualquer outro audio.
  3. Split automatico: o script separa os WAVs positivos em treino e teste.
  4. Augmentation: os positivos sao padronizados, deslocados e aumentados acusticamente.
  5. Extracao de features: o audio vira features no formato esperado pelo openWakeWord.
  6. Treino binario: o modelo aprende classe 1 para wake word e classe 0 para nao wake word.
  7. Exportacao: o melhor checkpoint e salvo como .onnx.

Passo a passo

1. Instalar dependencias

Crie uma virtualenv separada com Python 3.10 e instale as dependencias de treino:

py -3.10 -m venv ModelTraning\.venv_training
.\ModelTraning\.venv_training\Scripts\activate
python -m pip install --upgrade pip
pip install -r ModelTraning/requirements.txt

Esse arquivo usa PyTorch/Torchaudio 1.13.1 com CUDA 11.7, alinhado ao extra full do openWakeWord 0.6.0. O treino usa GPU automaticamente quando torch.cuda.is_available() retorna True. 

python -c "import torch; print(torch.cuda.is_available(), torch.version.cuda)"

2. Gerar os dados positivos

Rode o fluxo de DataGeneration para criar a pasta com WAVs positivos. Para Atlas, a pasta esperada hoje e: 

DataGeneration/Dataset-Atlas

Essa pasta deve conter arquivos como sample_00000.wav, sample_00001.wav etc.

3. Baixar assets do openWakeWord e negativos

Esse passo precisa rodar pelo menos uma vez por maquina/ambiente:

python ModelTraning/download_assets.py

Ele baixa os modelos internos de feature extraction para o pacote openwakeword instalado na venv ativa, alem dos arquivos em ModelTraning/assets. Os assets negativos sao grandes porque representam exemplos genericos de audio que nao devem ativar a wake word.

4. Preparar audios

Converta os WAVs positivos para a copia derivada em mono, 16 kHz, PCM_16:

python ModelTraning/train.py DataGeneration/Dataset-Atlas --stage prepare

5. Treinar

Para Atlas, rode:

python ModelTraning/train.py DataGeneration/Dataset-Atlas

Como a pasta chama Dataset-Atlas, o script infere o nome atlas e salva ModelTraning/models/atlas.onnx.

Durante a execucao, o terminal mostra as etapas do pipeline, contagens de arquivos, shapes dos arrays de features, barras de progresso e mensagens periodicas em operacoes longas. Use --no-visual-progress se quiser esconder esses indicadores extras.

6. Treinar outra wake word

Coloque os WAVs positivos em outra pasta e passe essa pasta ao script:

python ModelTraning/train.py DataGeneration/Dataset-Jarvis

Isso gera ModelTraning/models/jarvis.onnx.

Comandos uteis

Objetivo Comando
Preparar audios do Atlas python ModelTraning/train.py DataGeneration/Dataset-Atlas --stage prepare
Treino padrao do Atlas python ModelTraning/train.py DataGeneration/Dataset-Atlas
Definir nome manual do modelo python ModelTraning/train.py DataGeneration/Dataset-Atlas --model-name atlas_v2
Aumentar tempo de treino python ModelTraning/train.py DataGeneration/Dataset-Atlas --steps 50000
Refazer audios preparados python ModelTraning/train.py DataGeneration/Dataset-Atlas --overwrite-audio --stage prepare
Refazer split e features do zero python ModelTraning/train.py DataGeneration/Dataset-Atlas --overwrite-split --overwrite-features
Usar ruidos de fundo locais python ModelTraning/train.py DataGeneration/Dataset-Atlas --background-dir caminho/ruidos

Para que serve o JSON?

O JSON nao e obrigatorio e nao precisa existir para cada wake word. Ele serve como preset de parametros avancados do treino. Use JSON quando quiser repetir exatamente uma configuracao tecnica, nao quando quiser apenas treinar outra palavra.

Exemplos de parametros que cabem no JSON:

  • steps: quantidade de passos de treino.
  • batch_n_per_class: composicao do batch entre positivos e negativos.
  • background_dirs: pastas com ruidos de fundo para augmentation.
  • rir_dirs: pastas com room impulse responses.
  • target_false_positives_per_hour: alvo de falsos positivos por hora.
  • convert_to_tflite: exportar tambem TFLite.
python ModelTraning/train.py DataGeneration/Dataset-Atlas --config ModelTraning/training_preset.json

O preset real fica em ModelTraning/training_preset.json. Para o uso normal, nao crie outro JSON. Para Atlas, o comando direto ja e suficiente.

GPU, TensorFlow e TFLite

O treino padrao gera .onnx e usa PyTorch. Se o PyTorch instalado tiver CUDA e a GPU estiver disponivel, o script usa GPU automaticamente para a extracao de features e para o treino.

TensorFlow nao e necessario para treinar. Ele so entra na conversao opcional para .tflite, por isso ficou separado em ModelTraning/requirements-tflite.txt. Em Python 3.13, pins antigos como tensorflow-cpu==2.8.1 nao resolvem.

Observacoes importantes

  • A etapa --stage prepare cria uma copia derivada em 16 kHz mono PCM_16; os WAVs originais nao sao alterados.
  • Quanto mais variedade nos positivos, melhor: vozes, velocidades, acentos, volumes e ambientes.
  • Os assets negativos sao essenciais. Sem exemplos negativos, o modelo tende a ativar com qualquer fala.
  • O arquivo .onnx final e o artefato que deve ser usado na aplicacao principal.
